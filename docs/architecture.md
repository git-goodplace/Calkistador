# Архитектура и выбор стека

Решения ниже приняты под конкретное ограничение: приложение пишет один агент, команды
разработчиков нет, а продвигать продукт будет маркетолог. Значит, всё, что требует
постоянного обслуживания инфраструктуры, — это риск, а не возможность.

## Платформа: веб-приложение (PWA), не нативное

Решено в обсуждении RIGE-63. Коротко:

- **Монетизация через сторы из России в 2026 фактически закрыта.** Продажи иностранным
  пользователям через российский аккаунт Apple Developer запрещены, российская аудитория не
  может оплачивать покупки; Google Play с января 2025 не выплачивает российским
  разработчикам международные платежи. Деньги всё равно придётся принимать на своём сайте,
  значит веб нужен в любом случае.
- **Комиссия сторов 15–30% против ~3% у эквайринга.** На подписке 200–400 ₽/мес это
  решающая разница.
- **Мобильный UX обязателен.** Трата случается в магазине, не за ноутбуком. Поэтому веб, но
  mobile-first и устанавливаемый на домашний экран.

Чего PWA не даёт, и это принято осознанно: нет чтения SMS и push от банков (главный способ
полуавтоматического сбора данных в РФ — требует нативного Android), нет виджетов на домашнем
экране. Виджет заменяет Telegram-бот.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite | Статическая сборка без сервера. SSR продукту не нужен — все данные локальные. |
| UI | React + TypeScript | Типы обязательны: домен финансовый, ошибка в типе суммы стоит дороже скорости набора. |
| Стили | Tailwind CSS | Один файл конфигурации вместо дизайн-системы, которую некому поддерживать. |
| Локальное хранилище | IndexedDB через Dexie | Офлайн-first: операции пишутся без сети. |
| PWA | vite-plugin-pwa | Service worker, установка на домашний экран, офлайн-кэш. |
| Тесты | встроенный `node --test` | Ноль зависимостей: Node 22+ исполняет TypeScript напрямую. |

Домен (`src/domain/`) не зависит ни от React, ни от хранилища — это чистые функции над
числами. Их можно тестировать и переносить куда угодно, включая будущий бэкенд.

## Local-first, и это не только про удобство

Данные живут на устройстве; сервер появляется позже и только для синхронизации между
устройствами.

Это даёт неочевидную юридическую выгоду. Приложение для личных финансов собирает
персональные данные россиян, а 152-ФЗ требует хранить их в России — то есть хостинг в РФ
(Яндекс Облако, Selectel, VK Cloud) и уведомление в Роскомнадзор. Пока данные не покидают
устройство, этого обязательства нет вообще: нет сервера — нет обработки. Поэтому первый
этап проектируется без аккаунтов и без сервера, а синхронизация появляется этапом позже,
уже на российском хостинге и с осознанным решением про 152-ФЗ.

Это не юридическая консультация — перед выпуском вопрос нужно задать юристу.

## Деньги — всегда целые копейки

В домене нет ни одного числа с плавающей точкой. `0.1 + 0.2 !== 0.3` в double, и в
финансовом приложении такие расхождения всплывают в остатке по счёту и в сумме налога —
ровно там, где пользователь перестаёт нам верить. Тип `Kopecks = number` хранит целое число
копеек; округление до рубля — только на выходе, где этого требует НК РФ.

## Налоговые параметры — конфигурация, а не константы в коде

Ставки, лимиты и пороги меняются каждый год, а региональные ставки отличаются от
федеральных. Поэтому они собраны в `src/domain/tax/params-2026.ts` с годом и датой начала
действия, а пользователь может переопределить ставку вручную. В расчёте нет ни одного
налогового литерала.
